# crossbook audit — 2026-08-01

Eight independent auditors, one per dimension, against `8c3a72b`. Every finding
below was traced to code; findings marked **measured** were reproduced by
compiling a probe or running under a sanitizer, not inferred.

Nine defects and four inert gates are fixed in `e4b8574`. The rest is ranked
below, and the ranking is by *damage to the project's central claim*, not by
how hard it is to fix.

---

## The pattern worth naming

The single most common defect class here is not a wrong algorithm. It is a
**control that is reported as evidence and structurally cannot fail**:

| Control | What it claimed | What it did |
|---|---|---|
| CI job `determinism` | "checked on every platform rather than asserted in a README" | `ctest -R` filters names; those are tags. Ran 13 checksum tests and zero determinism or equivalence tests, green on 3 platforms |
| `test_determinism.cpp` | "identical input produces a bit-identical state hash on every platform" | Compared each platform's hash to *its own*. No constant, no cross-platform comparison |
| Contributing rule 1 | "both rules mechanically checked" | No static_assert, no lint, no grep. Nothing at all |
| `test_no_alloc.cpp` | "no allocation on the hot path, enforced by a test" | Drives a fixed touch, so it never enters `overflow_` or `rebuild_around_touch` — the only two places `ArraySide` can allocate |
| `round_trips()` | "documented, tested, and guarded at ingest" | Zero call sites outside tests, and the predicate is numeric so it cannot detect the non-canonical spelling it exists for |
| `kept_pace()` | "the precondition for reading these percentiles as steady-state latency" | Constant false — event 0's deadline is `wall_start`, read after `wall_start` (**measured 5/5**) |
| `overflow_size()` | exists "so benchmarks and tests can assert the window is doing its job" | No benchmark reads it |
| `ReplayOptions::speed` | "how you find the rate at which the handler stops keeping up" | Nothing ever sweeps it |

This is the same failure mode the README opens by criticising — "most order book
implementations are tested against themselves" — reappearing one level up, in
the tests and CI rather than in the book. Fixing these is cheaper than any
optimisation in this document and worth more.

## Fixed in `e4b8574`

Memory safety and UB (all reproduced first):

1. **`histogram.hpp` heap-buffer-overflow.** The sizing loop stopped one
   doubling short when the range is an exact power of two; `record` clamps
   everything above the range onto it, so *every* oversized sample wrote past
   the end. ASan-confirmed at `Histogram(2048, 3).record(2048)`. Invisible to
   the suite because no test used a power-of-two range.
2. **`histogram.hpp` constructor hang** for ranges above 2^63 — `covered <<= 1`
   wraps to zero and the loop never terminates.
3. **`histogram.hpp` `merge()` silently wrong.** Compared `counts_.size()`, but
   `(2e12, 3)` and `(30000, 4)` both size to 32768 with different value→index
   maps. Merging across them reported p50 off by 3×. Now compares layout and
   returns `bool`.
4. **`fixed.hpp` `checksum_token`** negated through the signed type: UB at
   `INT64_MIN`, and it emitted a `-` into a token documented as digits only.

Correctness:

5. **`sequence.hpp`: Binance spot ran the futures straddle rule.** Spot anchors
   at `lastUpdateId + 1`, futures at `lastUpdateId`. The first event after any
   resync begins at `lastUpdateId + 1` by construction, so spot read its own
   recovery as a fresh gap and demanded another snapshot — a resync loop on a
   contiguous stream, publishing a gap rate that measured the bug. The test
   suite had locked the wrong rule in.
6. **`feed.hpp`: `apply_snapshot` never checked `msg.ok()`.** A truncated REST
   body cleared the book, applied nothing, and set `synced_ = true`.
7. **`book.hpp`: `state_hash` collision.** Side tag mixed as just another
   mantissa, no level count, no separator — one bid at `(1,1)` hashed
   identically to one ask at `(1,1)`.

Gates:

8. CI `determinism` job now runs the binary with a Catch2 tag spec (exits
   non-zero on an empty selection). 13 → 27 cases.
9. Golden cross-platform hash constant `0x5EA7472EED71E53E`.
10. Float-ban CI gate over the book path (verified to fail when `histogram.hpp`
    is added to the file list).
11. `replay.hpp` 1 ms schedule lead-in; test tolerance `<= 2` → `== 0`.

Performance:

12. `count_leading_zeros` → `std::countl_zero`. ~15 ns of a 22.5 ns `record()`,
    which runs inside the replay measurement loop.

204 cases / 70,884 assertions green.

> The histogram regression test asserts `bucket_total() == count()`, not "it
> ran". The first version of that test **passed with the bug reintroduced** — a
> release-build vector write past the end is silent. Worth remembering when
> writing the tests below.

## Status: all of the below is now fixed

Everything in the ranked list that follows has been implemented, tested, and
merged. It is kept as the record of what was wrong and why, because the
reasoning is worth more than the diff.

**Final state:** 325/325 ctest on a clean `-Werror` build, 324 Catch2 cases /
73,237 assertions, plus the self-containment object library (26 generated TUs)
and a compiled-and-run example.

**41 defects fixed across 6 subsystems.** The measured headlines:

| | before | after |
|---|---|---|
| `ArrayBook::apply`, 40k-tick span | 25,000 ns, 90 allocs/update | **17.9 ns, 0 allocs** |
| `ArrayBook::apply`, 1M-tick span | 405,179 ns, 2,982 allocs/update | **1,765 ns, ~0 allocs** |
| `Histogram::record` | 22.5 ns | **9 ns** |
| CI `determinism` job | 13 checksum tests, 0 determinism tests | **39 cases, 5,052 assertions** |
| touch read, array vs map | "1.33 vs 2.67 ns" (two different units, work hoisted) | **1.33 vs 1.36 ns/call — a tie** |
| `crossed()` on a normal BTC book | fired permanently | correct |
| Binance spot resync | never converged | converges |
| Kraken staleness detection | structurally dead | works |
| `round_trips()` ingest guard | 0 call sites, wrong predicate | byte-wise, called on every level |

**What did not get done, and why.** MSVC 19.30 is still an untested claim:
hosted runners ship only the 14.4x toolset, so the floor cannot be exercised
without a self-hosted image. Lowering the claim to match the runner would be
the wrong direction, so it is documented as untested in `ci.yml`. The new
`fuzz_json.cpp` builds clean and its oracles hold on current code, but libFuzzer
needs Clang and none was available here — it has not actually been fuzzed yet.
And no seed corpus is committed, so CI's first fuzz run still starts cold; the
cache added means the second onward starts warm.

## The ranked list, as found



### 1. Merge `feat/live-transport` — it carries a correctness fix `main` lacks

`main` and `feat/live-transport` have diverged (1 commit vs 4). The branch has
TLS websocket transport, `capture.hpp`, `crossbook_verify`, a committed 73 KB
Kraken capture replayed in CI, a golden state hash, **and**:

```
5dece2b fix(book): trim depth-limited books, or their checksums eventually fail
```

`main` has no `trim`. On a depth-limited subscription its checksums will
eventually fail — the flagship claim, broken on the default branch, already
fixed on a branch nobody merged. This is the highest-value action in the repo
and it is not new work.

Merging also discharges: no captured corpus, determinism untested across
platforms, "reproducible by anyone who clones it" (false on `main` — there is
no transport), and the absence of any published match rate.

### 2. Venue protocol — three ways a book corrupts undetected

- **No symbol validation anywhere.** `venues/binance.hpp:98`,
  `venues/kraken.hpp:128` read the wire symbol; `feed.hpp:230` applies every
  level regardless. `grep spec_.symbol include/crossbook/venues/` → nothing.
  Binance *advertises* combined-stream support (`binance.hpp:81-86`) — it
  unwraps the multiplexed envelope and implements none of the routing that
  envelope exists for. An ETH level lands in a BTC book and no later delete
  ever arrives. On Kraken the checksum catches it; on Binance nothing does.
- **Kraken multi-entry `data` arrays silently truncated** to entry #1 and
  reported `ok` (`kraken.hpp:103-106`: early `false` from `for_each` reads as
  success). Entries 2..N vanish with no error and no divergence.
- **Kraken `timestamp` is never parsed**, so `msg.ts` is always 0, so
  `feed.hpp:168` short-circuits and `check_staleness` is structurally dead on
  the only venue with checksums. **Measured: 1 h of silence → `synced() ==
  true`.** The one staleness test uses Binance.

Also: a present-but-unparseable Kraken `checksum` falls through to
`has_checksum = false` with `error == kOk` (`kraken.hpp:132-139`), so a venue
switching the field to a string turns off all verification while `match_rate()`
stays 1.0.

### 3. `ArrayBook` performance cliff — measured, and it violates both stated rules

`rebuild_around_touch` (`book.hpp:361-368`) heap-allocates and `std::fill`s
512 KiB *inside* `apply()`. Past a 65,536-tick live span it thrashes:

| live span | `MapBook` | `ArrayBook` | allocs/update |
|---|---|---|---|
| 5,000 ticks (widest benchmarked) | 193 ns | **12.5 ns** | 0 |
| 40,000 ticks | 214 ns | **30,617 ns** | 84 |
| 1,000,000 ticks | 194 ns | **773,083 ns** | 5,192 |

The published benchmark stops at 5,000 and the equivalence test's widest spread
is 5,000. **The cliff sits immediately past the last measured point**, and a
Binance full-depth book routinely spans it. This is the same shape as the
best-index story the README tells proudly — correct, passing its tests, and
unusable — recurred one layer out.

Also `test_book_equivalence.cpp:145` asserts `overflow_size() <=
kOverflowRebuildThreshold`, an invariant the implementation does not provide;
it holds for the chosen generator and nothing else.

### 4. The headline number governs 1.4% of the frame

Measured, one Kraken update, end to end:

| stage | ns | share |
|---|---:|---:|
| `decode` (JSON) | 960 | **65%** |
| `kraken_checksum` | ~500 | **34%** |
| `apply` | 16–21 | **1.4%** |

Swapping the tick-indexed array for `std::map` costs **8.6% end to end**, not
8.5×. `json::find` has no resume point, so a frame is walked **9.3× measured**;
the CRC is byte-at-a-time, entered once per level with ~12 bytes each. Neither
is benchmarked — there is no `BM_KrakenDecode` and no `BM_FeedHandle`.

Cheapest real wins: a `for_each_member` primitive collapsing the per-key
restarts (~60 lines, decode 960 → ~430 ns) and buffering all 20 levels for one
slice-by-4 CRC (~35 lines, 495 → ~250 ns). Together ~2.1× end to end.

**Add the end-to-end benchmark first.** Without it none of the above is
arguable, and the README currently leads with the one component that does not
matter.

### 5. `int64` wraparound in the window index math

`book.hpp:145,149,384`: unguarded signed subtraction on venue-controlled
values. The wrapped offset can land *back inside* the window, so a price at the
opposite end of the `int64` range files next to the touch and `for_each` stops
emitting in price order. Reachable: `parse_fixed("9223372036854775807", 0)`
succeeds and both decoders feed the result straight into `Price{}` unchecked.
Do the arithmetic in `uint64` (wrap is defined) and use `offset < slots_` as the
in-window predicate, which is wrap-immune.

Both differential generators exclude this by construction — `fuzz_book.cpp:38`
draws prices from exactly a 65,536-wide band, which is exactly the window.

### 6. `consolidated.hpp` — cross-venue comparison with no dimensional checking

The `CentiBps` truncation bug was found and fixed independently while this audit
ran. Still open:

- **Scale and symbol mixing undetected.** `spec_` is stored, exposed, and never
  read. `VenueQuote` carries no scale. Kraken at `price_scale=1` and Binance at
  `price_scale=2` in one book: Binance wins every bid ranking and loses every
  ask ranking, forever, and qty-scale mixing corrupts the VWAP weights with no
  symptom at all.
- **Staleness fails open on unstamped quotes.** `received_at{0}` is the struct
  default and the guard requires `received_at > 0` to *exclude* — so a quote
  nobody timestamped is immortally fresh.
- **Rounding is trader-optimistic on every path** — asks understated, bids
  overstated. Enough to invert venue ranking; worked example in the swarm log.
- **Ties broken by arrival order**, which is the one thing that differs between
  two processes reading the same market.
- **`ranked()`/`best()` allocate** on the touch-read path, after `book.hpp`
  went to some trouble to make that question O(1) and allocation-free.

### 7. Packaging — the documented consumption path does not work

- README pins `GIT_TAG v0.1.0`; `feed.hpp`, `json.hpp`, `venues/` **do not exist
  at that tag**. Copy-paste the FetchContent block, then the pipeline example,
  and it does not compile. Three versions disagree: README says v0.3, tag is
  v0.2.0, `CMakeLists.txt:4` says 0.1.0.
- `target_link_libraries(crossbook INTERFACE crossbook_warnings)`
  (`CMakeLists.txt:79`) exports `-Wconversion -Wsign-conversion /permissive-
  /utf-8` onto **every consumer's own translation units**. It will also
  hard-error the moment an `install(EXPORT)` is added.
- No export set, no package config → `find_package(crossbook)` cannot work.
- Several headers are not self-contained (`fixed.hpp` uses `std::size_t` with
  no `<cstddef>` — and it is the base of the dependency tree). No test can
  catch it: every TU includes Catch2 first, which drags in most of the STL.

One CI job — build crossbook as a *consumer* would — catches all four.

### 8. README claims that do not survive checking

- *"almost nobody collects it"* — cryptofeed has had checksum validation across
  six venues since 2020; NautilusTrader does Kraken by default. The defensible
  claim is narrower and better: **everyone else makes it optional because it
  costs 10–100 µs; here it is 506 ns, so it is not a flag.**
- *"the commit history has both"* (the best-index anecdote) — `git log -S
  best_index` returns only the initial commit. The one place the README says
  "don't take my word for it" is the one that fails. The depth-trim bug on
  `feat/live-transport` is a strictly better story *and* it is genuinely in
  history.
- *"five independent mechanisms"* — one external oracle and four internal
  consistency checks. Saying so is more impressive, not less.
- *"physically cannot"* about `double` — `printf("%.1f")` round-trips exactly.
  The real argument (a formatting step that costs more than the comparison and
  must be exactly right at every scale) is strong; the absolute invites a
  correction.
- Stale counts: "139 test cases / 841 assertions" (now 204), "four fuzz targets"
  (five built, `fuzz_l3.cpp` present but **not registered** in
  `fuzz/CMakeLists.txt`), `json.hpp:26` cites a `fuzz_json.cpp` that does not
  exist, and `execution.hpp`/`consolidated.hpp` ship while Status lists them as
  unbuilt v0.4.

Every disclaimer in the README is attached to a performance number and none to a
correctness claim — which is backwards for this library, and is why the
unhedged sentences are the ones that did not survive.

## Method note

Two of the eight agents independently found the inert `determinism` CI job; two
independently concluded that merging `feat/live-transport` is the highest-value
action. Convergence from agents that could not see each other is the reason
those two sit at the top.

Findings were re-verified against `HEAD` before being acted on — the repo moved
under the swarm mid-run, and one critical finding (`CentiBps` truncation) had
already been fixed by the time the report landed.
